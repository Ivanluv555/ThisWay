### 5.2 简化拥挤模型的最小输入

| 层级 | 输入 | 单位与更新方式 |
| --- | --- | --- |
| 区域静态 | 区域 ID、功能类型、核定容量、可选空间类型 | 初始化维护；容量为人；不随每次计算上报 |
| 景区动态 | 天气、管控状态、采集时间 | 一个景区共用；每周期采集 |

设计层保留有效面积 `area_m2`，当前纯算法的 `ZoneInput` 直接使用 `max_capacity`，不以面积推导容量。区域功能 `zone_type` 与空间形态 `space_type` 分开，不能将 CORE 等同于“开敞”。后者缺失时，代码回退到功能类型折减映射。

### 5.3 区域与景区公式

有效容量、负载比：

$$C_i^{eff}=C_i^{max}\kappa_i\eta_{weather}\eta_{manage},\qquad r_i=N_i/C_i^{eff}$$

默认天气系数：晴/多云 1.0、小雨 0.85、中雨 0.70、暴雨 0.50。默认管控系数：正常 1.0、限流 0.85、封闭/施工 0.60。这些是量化模型映射，不能据此推导实际封闭后仍可售票。

默认阈值 $r_1=0.6,r_2=0.8$：

$$\Phi(r)=\begin{cases}0.5r&r<r_1\\0.3+1.5(r-r_1)&r_1\le r<r_2\\0.6+0.4(1-e^{-4(r-r_2)})&r\ge r_2\end{cases}$$

服务区 ENTRY/RIDE/TOILET/DINING 使用排队项 $Q=\min(1,W/30)$，缺失等待时间时取 0：

$$CI_i=\min(1,0.85\Phi(r_i)+0.15Q_i)$$

其他区域 $CI_i=\min(1,\Phi(r_i))$。服务区在 $Q=0$ 时仍乘 0.85，这是当前实现，而非直接回退到非服务区公式。

默认区域权重：CORE 1.50、RIDE 1.40、TOILET 1.30、ENTRY 1.20、EXIT/EXHIBIT 1.10、DINING/TRANSIT 1.00、SHOP 0.90、PATH 0.80、PARKING 0.75。

$$SCI_{base}=\frac{\sum_iw_iCI_i}{\sum_iw_i},\quad SCI_{peak}=\max_{i\in\{CORE,ENTRY,RIDE\}}CI_i$$

$$SCI=\min(1,0.7SCI_{base}+0.3SCI_{peak})$$

代码在没有关键区域时令峰值为 0。纯算法检查非负人数、正容量和字典映射；业务模板调用 `strict=False`。这不等于已经具备数据缺失队列或现场质检系统。

### 5.4 输出口径

| 指标 | 范围 | 当前来源/等级 |
| --- | --- | --- |
| 区域/景区核心指数 | 0–1 | 简化公式；原设计等级边界为 0.25/0.50/0.70/0.85 |
| `congestionIndex` | 0–10 | 模板聚合结果乘 10 |
| 预测记录 `crowdDensity` | 0–10 | $\min(10,10\hat N/C)$，并非区域聚合，也不是人/平方米 |
| `trafficLevel/congestionLevel` | 1–5 | 预测指数按 ≤2、≤4、≤6、≤8、>8 划分 |
| `trend` | 上升/下降/平稳 | 预测量与历史均值之比 >1.05、<0.95、其他 |

旧 Flask API 文档出现过 0.75/0.90 的等级阈值，不能沿用到当前指数。数据库字段命名尚需进一步统一，接口展示必须带清楚口径。

### 5.5 LSTM 预测与数据准备

1. Spring 提供景点和最近 `HISTORY_HOURS` 小时历史，默认 168 小时。
2. 记录不足 `景点数×24` 时，生成模拟历史；该判断只看总条数，不保证每景点都有连续 24 小时。已有历史转成时间×景点矩阵，前向填充后补 0。
3. MinMaxScaler 归一化，序列长度默认 12、隐藏维度 64、batch 16，Adam 学习率 0.001，MSE 训练 60 epochs。
4. 逆变换得到下一小时各景点人数，负值截到 0。容量按历史 P95×1.15、均值×1.40、3000 三者最大值估算，不是实测核定容量。
5. 请求默认 `write_back=true`，写入模拟基线、预测和转移。写回异常可能被捕获后继续返回摘要，必须读回当轮记录才能确认持久化。

没有已存模型权重的加载流程；每次重新训练。未实现模型注册、滚动回测和正式准确率报告。

### 5.6 分流建议与下一目的地

分流策略先按超安全客流排序源景点，筛选距离可达且有余量的目标；根据余量、距离相似度、优惠强度形成候选评分，再计算接受概率和条件选择概率：

$$\widetilde P_{ij}=\pi_iP(j\mid接受),\qquad F_{ij}=\hat N_i\widetilde P_{ij}$$

保留原计划的概率为 $1-\pi_i$。`finalProb` 写入 `transitionProbability`，`expectedTransferFlow` 取整写入 `expectedUsers`，`coupon` 写入 `couponAmount`。优惠金额是模型建议，不代表优惠券已发行或核销。

Java 查询最新源景点记录后取 Top 3，按 `hours` 重复为小时标签。各小时概率/人数相同；Top 3 概率也不要求归一为 100%，因为仍存在保留原计划和其他候选项。前端仅在 HTTP 异常时生成 fallback，空数组不会触发 fallback。

### 5.7 调度接口与状态

```bash
# 独立测试服务，写入测试库
curl -X POST 'http://127.0.0.1:8001/prediction/scheduler/toggle?enabled=true'
curl 'http://127.0.0.1:8001/prediction/scheduler/status'
curl -X POST 'http://127.0.0.1:8001/prediction/run-now'
curl -X POST 'http://127.0.0.1:8001/prediction/scheduler/toggle?enabled=false'
```

每 30 秒检查，整点后约两分钟窗口内触发；定时成功记录用于同小时去重。时间来自主机 `datetime.now()`，部署时应统一主机时区。应用启动默认不启用调度。

状态含 `running/stopping/startedAt/lastPredictAt/lastError/predictionCount/lastSummary/nextScheduledHour`。手动执行不更新所有调度状态；写回失败也可能不体现在 `lastError` 中。需补任务互斥、失败分类、幂等和多 worker 行为验证。

模拟器独立启停，默认每 60 秒生成一次数据；批量接口 `/flow/simulation/batch-insert?hours=24&lookback=true` 可填历史。这属于数据生产操作，不是只读健康检查。

### 5.8 研究方案与实现差距

| 研究阶段 | 要解决的问题 | 当前覆盖 |
| --- | --- | --- |
| MDS 时序距离与 K-means 分组 | 选关联景点 | 未纳入当前预测管线 |
| LSTM + AR 多基预测器 | 非线性与线性规模补偿 | 有单套多变量 LSTM，无 AR 融合 |
| 网格/天气/节假日注意力 | 外生因素、空间关联 | 未见完整特征接入与注意力实现 |
| 分位数 0.1/0.5/0.9 与 pinball loss | 预测区间与场景 | 当前为 MSE 点预测 |
| 非强制选择与激励 | $U=\beta_0+\beta_1x-\beta_2d-\beta_3CI+\beta_4sim+\beta_6r$ | 有启发式接受/选择策略；参数未有实测标定报告 |
| 用户均衡、配额、预算多目标优化 | 安全、等待、激励成本、收益、均衡 | 未见完整约束优化求解 |
| CVaR、MDP、RL/MPC | 不确定性与滚动控制 | 研究方向，未实现 |

保留的研究骨架：候选集合包含原目的地；OD 流量非负且守恒；激励总额不超预算；配额上下限及变化率受约束；每次只执行当前步并以真实反馈滚动更新。多目标可写为安全超载惩罚、等待、激励成本、负收益和景区间方差的加权和；鲁棒目标为 $E[J]+\eta CVaR_\alpha(J)$。

原方案引用 Bi et al. (2023)、Sun et al. (2023)、Yamada & Kamiyama (2021)、Gehlota et al. (2020)，目前缺完整题名/出处/DOI，不能作为已核验的文献结论。原 softmax 调权中的景区压力若对所有预测器相同，会作为公共加法项抵消，需要先修正数学定义。

### 5.9 可验收的模型评估

按时间划分训练/验证/测试集，记录真实与模拟数据占比；使用历史同小时、均值或其他简单预测作基线。至少报告 MAE/RMSE、各景点与峰值时段误差，以及分流前后峰值指数、超载景点数、跨景区方差和预算消耗；区间模型实现后再评 PICP。记录版本、种子、样本窗口、参数、硬件和原始输出，不能以示例图或假设收益代替实验结果。
