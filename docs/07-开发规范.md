## 07 开发规范

### 7.1 代码与目录

- 后端 Java 参考团队选定的《阿里巴巴 Java 开发手册》；Python 遵循 PEP 8。
- 单份代码文件原则上不超过 1200 行；按职责拆分，禁止为了满足行数机械切割。
- 业务阈值、枚举与配置使用有含义的名称，说明单位与来源，避免不可解释的硬编码。
- 待办使用 `TODO: 描述`，可关联问题编号；上线前明确其影响与处理决定。
- 业务代码放 `devs/` 对应模块，说明文档集中 `docs/`；根 README 与标准政策文件仅作入口，依赖清单、LICENSE 和运行时模板保持工程所需位置。

### 7.2 Git 协作

```text
type(scope): message

可选正文：修改目的、关键决策与验证结果。
```

类型：`feat` 功能、`fix` 缺陷、`refactor` 重构、`docs` 文档、`test` 测试。按一件独立变更提交，提交前检查差异，避免误带配置和凭据。

功能分支采用 `feature/开发者/功能描述`。提交 PR 后审查代码与文档，解决冲突并通过必要验证后合并；合并不等于自动具备生产发布条件，发布遵循 [06 部署与验证](./06-部署与验证.md)。

协作与评审遵守 [15 贡献者行为准则](../CODE_OF_CONDUCT.md)。安全问题按 [14 安全政策](../SECURITY.md) 私密报告，公开 PR 不附凭据、真实用户数据或未修复漏洞的利用细节。

### 7.3 文档规则

| 约定 | 要求 |
| --- | --- |
| 命名 | `两位序号-主题.md`；专题资源目录使用相同形式；`README.md` 作为目录入口；根 `SECURITY.md`、`CODE_OF_CONDUCT.md` 只链接编号正文 |
| 标题 | 正文从 `##` 开始，子标题递进，编号与文件主题一致 |
| 内容 | 写职责、契约、输入输出、操作和验证；删除重复背景、口号、假设收益与空占位 |
| 来源 | 代码事实链接源码；研究资料注明出处和核验状态；估算不能写成实测 |
| 版本 | 关键基线、校验日期与适用模块明确；已实现、模拟、规划分开 |
| 链接 | 使用仓库相对路径；移动时同步引用，禁止个人机器绝对路径 |
| 图示 | 目录树、文本结构和流程使用 Mermaid 代码块，不使用 ASCII 拼图；业务/技术总体图保留 Excalidraw，源文件与 SVG/PNG 同步更新 |
| 更新 | API、配置、schema、算法变化与代码在同一变更中更新文档 |

主信息维护位置：业务与技术总览在 01，运行变量在 02，接口在 03，数据字典在 04，算法在 05，部署/验证在 06，缺陷与证据在 08，安全政策在 14，贡献者行为准则在 15。其他文件引用主位置，不重复维护另一套契约。

模块负责人维护对应说明，跨模块接口由调用方和提供方共同核对。需要团队通知时由成员通过团队约定渠道完成；自动化整理不会代发消息。
