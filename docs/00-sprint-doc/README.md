### 前置说明


#### 分级方法

敏捷 / 产品通用，MoSCoW 优先级

#### 功能实现优先级定义

- 等级 P0 ：
  - **必须实现（Must）**
  - 产品核心底线，不做则系统不可用、业务无法闭环、违反合规 / 合同，本版本必须上线。
- 等级 P1：
  - **应该实现（Should）**
  - 核心流程的重要补充，缺失会显著影响体验 / 效率，但不阻断主流程，本版本强烈建议上线。
- 等级 P2：
  - **可以实现（Could）**
  - 锦上添花，优化体验、小众场景、非核心效率提升，资源充足才做。
- 等级 P3：
  - **本次不做（Won't）**
  - 已认可但本迭代不纳入，放入后续版本 / 需求池。

#### 专业判定原则

1. 业务价值：是否影响营收、核心流程、合同交付
2. 用户影响面：是否所有用户 / 核心用户 / 小众用户
3. 合规 / 安全：是否涉及法律、隐私、风控、审计
4. 风险：是否会导致故障、投诉、线上事故

定级铁律：
- 合规 / 安全 / 故障修复 ＞ 核心业务 ＞ 体验优化 ＞ 小众需求
- P0 必须极少（通常≤5%），否则等于没有优先级
