## 03 接口契约

> 基线：2026-11-06，按当前路由声明与数据模型整理。表中“存在”不代表实际运行通过；已知跨服务不一致见 [08 项目状态](./08-项目状态与待办.md)。

### 3.1 三套服务必须区分

| 服务 | 本地端口 | 路径/格式 | 文档入口 |
| --- | --- | --- | --- |
| Spring Boot | 8080 | `/api/*`，成功多为实体/数组；错误有统一结构 | `/doc.html`、`/v3/api-docs` |
| FastAPI | 8001 | 无统一 `/api` 前缀，Pydantic 请求/响应 | `/docs`、`/openapi.json` |
| Flask 原型 | 5000 | `/api/v1/*`；算法响应 `code/message/data` | `/api/v1/doc` 是运行时搜索/详情 HTML |

Java 登录返回 Token，但当前未见统一 JWT 请求过滤器；接口不能宣称已经强制鉴权。小程序 HTTP 封装默认 `withAuth=false`，调用者需明确认证约定。

### 3.3 认证与业务参数

| 操作 | 输入 | 输出/说明 |
| --- | --- | --- |
| `POST /api/auth/wechat/login` | JSON `code`，可选 `nickname/avatarUrl` | `token/expiresAt/wechatEnv/user`；昵称落入用户 `username` |
| `POST /api/auth/wechat/phone/bind` | JSON `userId/code` | `userId/phone/newlyBound` |
| `GET /api/flow/history` | Query `hours=168`、可选 `locationId` | `LocationHourlyFlowDTO[]`，camelCase 字段 |
| `GET /api/flow/history/latest` | 可选 `locationId` | 每景点最新一条；不是 `/api/flow/latest` |
| `POST /api/flow/history/batch` | JSON 客流 DTO 数组 | 保存结果数组；直接 `saveAll`，不是按景点/小时 upsert，重复键可能失败 |
| `POST /api/spot-traffic-predictions/batch` | JSON 预测实体数组 | 缺 `createTime` 时补当前时间 |
| `GET /api/spot-traffic-predictions/latest` | 无 | `predictTime` 最大的整轮数据 |
| `GET /api/spot-traffic-predictions/recent/crowd-density-asc` | 无 | 按创建时间取最近 21 条再按拥挤值排序；不保证是完整同轮 |
| `GET /api/location-transitions/next-destinations/{sourceLocationId}` | Query `hours=6` | 每行 `hour/transitions[]`；Top 3 同轮数据按小时复用 |
| `POST /api/location-transitions/batch` | JSON 转移实体数组 | 保存结果数组；缺创建时间时补齐 |
| 关注/取消关注/是否关注 | Query `followerId/followedId` | 分别为资源、204、布尔值；关注自己返回请求错误 |
| 关注列表/粉丝列表/统计 | 路径 `userId`，可选 Query `currentUserId` | 列表 DTO 或统计 DTO |
| 用户设置 GET/PUT/reset | 路径 `/api/user-settings/user/{userId}`；PUT 为设置 JSON | 不存在时返回默认设置，reset 另加 `/reset` |

不存在的“当前用户 `/users/me`”、管理员登录、后台反馈处理与文件上传，不写作已提供能力。所有资源字段和 SQL 类型见 [04 数据设计](./04-数据设计.md)，认证 DTO 见对应控制器引用。

下一目的地结构：

```json
[{"hour":"15:00","transitions":[{"locationId":5,"locationName":"示例景点","ratio":0.18,"ratioText":"18%","users":450}]}]
```

客流 DTO 的最小写入示例：

```json
[{"locationId":1,"recordHour":"2026-11-06T14:00:00","visitorCount":1200,"congestionIndex":3.2,"dataSource":"simulated"}]
```

### 3.4 Java 错误响应

```json
{"timestamp":"2026-11-06T14:00:00","status":404,"code":"REQ-404","message":"资源不存在: id=1","path":"/api/locations/1"}
```

`code` 是业务代码字符串，不是枚举名称；以 `ErrorCode.java` 与全局异常处理器为准。

| code | HTTP | 枚举/含义 |
| --- | --- | --- |
| `SYS-500` | 500 | `INTERNAL_SERVER_ERROR`：服务器内部错误 |
| `REQ-400` | 400 | `BAD_REQUEST`：请求参数错误 |
| `REQ-422` | 422 | `VALIDATION_FAILED`：请求参数校验失败 |
| `REQ-401` | 401 | `UNAUTHORIZED`：未授权访问 |
| `REQ-403` | 403 | `FORBIDDEN`：没有权限访问该资源 |
| `REQ-404` | 404 | `RESOURCE_NOT_FOUND`：资源不存在 |
| `REQ-405` | 405 | `METHOD_NOT_ALLOWED`：请求方法不被允许 |
| `REQ-415` | 415 | `UNSUPPORTED_MEDIA_TYPE`：不支持的请求体类型 |
| `WX-502` | 502 | `WECHAT_API_ERROR`：微信接口调用失败 |
| `WX-503` | 502 | `WECHAT_IDENTIFIER_MISSING`：微信接口未返回可用标识 |
| `WX-504` | 500 | `WECHAT_CONFIG_MISSING`：微信配置缺失 |
| `WX-505` | 400 | `WECHAT_INVALID_CODE`：微信登录凭证无效 |
| `WX-506` | 502 | `WECHAT_PHONE_NUMBER_MISSING`：微信接口未返回手机号 |
| `USR-409` | 409 | `PHONE_ALREADY_BOUND`：手机号已绑定其他用户 |

### 3.5 FastAPI 路由清单

按 `main.py` 装饰器整理，参数栏保留查询参数名称；必填、约束、请求/响应模型最终以当前 OpenAPI 和 [models.py](../backend/cidi-model/app/models.py) 为准。未实启 OpenAPI，不能把静态盘点当作线上接口探测。

| 方法 | 路径 | Query 参数 | 功能 |
| --- | --- | --- | --- |
| GET | `/health` | — | 返回进程状态与 Spring 基址 |
| POST | `/predict` | `hours=config.HISTORY_HOURS`、`write_back=True` | 训练下一小时客流、计算分流并可写回 |
| GET | `/predictions/latest` | — | 直接从 Spring Boot 获取最新一轮预测结果（用于前端展示） |
| GET | `/crowd-index` | `location_id=None` | 读取 location_hourly_flow 最新客流数据并计算拥挤指数。 |
| POST | `/prediction/scheduler/toggle` | `enabled（必填）` | 启停定时预测服务（每整点自动触发预测并写回数据库）。 |
| GET | `/prediction/scheduler/status` | — | 查询定时预测服务当前状态。 |
| POST | `/prediction/run-now` | — | 立即执行一次预测（手动触发，不等待整点）。 |
| POST | `/flow/simulation/toggle` | `enabled（必填）` | 启停模拟定时上报任务（单实例，后台非阻塞执行）。 |
| GET | `/flow/simulation/status` | — | 查询模拟定时上报任务当前状态。 |
| POST | `/flow/simulation/batch-insert` | `hours（必填）`、`lookback=False` | 一次性生成并上报指定小时数的模拟数据（开发测试用）。 |
| GET | `/locations/ids` | — | 读取 locations 全量景点并返回 ID 列表（当前测试集即重庆景点）。 |
| GET | `/spots/district-code` | `keyword（必填）` | 通过地点名称查询携程搜索结果，并解析最可能的 district_code(district_id)。 |
| GET | `/spots/all` | `keyword='重庆'` | 遍历指定地点景点并同步 MySQL；现有函数注释已过期。 |
| POST | `/spots/sync` | `keyword（必填）` | 同步入口：参数仅地点字符串。分页由服务内部控制，不对外暴露。 |
| POST | `/spots/details/sync` | `keyword（必填）` | 异步同步指定地区的景点详情，立即返回任务已受理。 |
| GET | `/spots` | `keyword='重庆'`、`pageIndex=None`、`pageSize=None`、`page_index=None`、`page_size=None` | 通过携程景点搜索接口查询景区数据。 |
| GET | `/spots/{district_code}/{sight_code}` | — | 通过携程景点详情页查询指定景区详细数据（含介绍、政策、设施、问答、点评与图片）。 |

`POST /predict` 返回 `predictions/flowBeforeAfter/pairRecommendations/summary`；预测记录字段 `spotId/predictTime/visitorCount/congestionLevel/trend/trafficLevel/crowdDensity/createTime`，转移字段见 04。`hours` 为 24–720，`write_back` 默认 true。`/health` 只返回进程信息和 Spring 地址，不保证数据库或算法健康。

`POST /prediction/run-now` 成功体是 `status/message` 加展开的摘要字段，和 `/predict` 的嵌套 `summary` 不同。模拟批量 `hours` 为 1–720，成功状态码 201；`lookback=false` 默认向未来生成。

`GET /spots/all` 和 `POST /spots/sync` 目前调用同一采集同步服务，都会写入 `spider_*`，前者虽然是 GET 也不是只读操作。详情同步成功受理返回 202，不代表后台抓取与写库已完成。

### 3.6 Flask 原型接口

| 方法与完整路径 | 输入 | 功能 |
| --- | --- | --- |
| `GET /api/v1/search` | `keyword=重庆/pageIndex=1/pageSize=12` | 景点搜索 |
| `GET /api/v1/spot/detail` | `district_code/sight_code` | 景点详情 |
| `GET /api/v1/doc` | 无 | 运行时 HTML 文档 |
| `POST /api/v1/algorithm/crowd_index` | `scenic_id/scenic_name/zones[]/zone_states` | 旧复杂景区指数 |
| `POST /api/v1/algorithm/zone_crowding` | `zone/state/upstream_crowding` | 旧复杂区域指数 |
| `POST /api/v1/algorithm/multi_scenic` | `scenic_areas/scenic_states/visitor_counts` | 旧多景区联动 |

算法 zone 输入包含 `zone_id/name/zone_type/area/max_density`，可选 `service_rate/service_windows/space_form`；state 包含 `visitor_count/timestamp/queue_count` 与天气、活动、设施、照明系数。输出为 `code/message/data`，`data` 可含 `crowding_index/crowding_level/zone_results`。枚举和默认值以 [algorithm_bp.py](../backend/cidi-mock/app/api/algorithm_bp.py) 与旧模型数据结构为准，不能把参数用于当前 FastAPI 简化模型。

### 3.7 前端适配约定

用户名称为 `username`，景点名称为 `title`，动作是 `postId + type(like/collect)`，预测是 `spotId/predictTime`。不要回用旧字段 `nickname/name/target_type/action_type/locationId/predictionTime` 充当相同资源契约。

`api/prediction.js` 委托 `api/cidi.js`；`getFuturePrediction` 查询 latest，`getNextDestinationForecast` 查询源景点转移，`getRecommendedSpots` 查询最近 21 条排序。新增适配函数不等于页面已使用；前端冲突未解决前不能保证整段文件可执行。
