# cidi-model 项目架构文档

## 模块划分

### 1. 应用层 (`app/`)

#### 1.1 算法模块 (`app/algorithms/`)
**职责**: 核心算法实现，独立于业务逻辑

- `crowd_index_calc.py`: 景区拥挤指数计算模型
  - 基于区域承载力的分段函数模型
  - 支持天气、管控状态等外部因素
  - 包含服务型区域排队修正
  - 提供景区级聚合计算

**设计原则**:
- 纯函数式设计，无副作用
- 完整的类型注解
- 可独立测试和复用

#### 1.2 服务层 (`app/services/`)
**职责**: 业务逻辑封装，协调算法与数据层

- `crowd_index_service.py`: 拥挤指数服务
  - 将景点客流映射到功能区模板
  - 调用算法模块计算拥挤指数
  
- `flow_simulation_service.py`: 客流模拟服务
  - 定时生成模拟客流数据
  - 支持批量历史数据生成
  
- `spot_sync_service.py`: 景点同步服务
  - 协调爬虫与数据库写入
  - 处理景点数据去重与更新
  
- `spot_detail_sync_service.py`: 景点详情同步
  - 异步批量同步景点详情
  - 控制请求频率避免封禁
  
- `district_lookup_service.py`: 地区查询服务
  - 解析地点名称到携程 district_code
  
- `visitor_profile_service.py`: 游客画像服务
  - 游客行为模式分析（预留）

#### 1.3 爬虫模块 (`app/spider/`)
**职责**: 外部数据采集

- `xc_spot_search.py`: 携程景点搜索爬虫
  - 分页搜索景点列表
  - 解析景点基础信息
  
- `xc_spot_detail.py`: 携程景点详情爬虫
  - 获取景点详细信息
  - 解析介绍、政策、设施等

#### 1.4 核心模块
- `config.py`: 配置管理
  - 环境变量读取
  - 默认值定义
  
- `models.py`: 数据模型
  - Pydantic 模型定义
  - API 请求/响应结构
  
- `predictor.py`: LSTM 预测模型
  - 客流预测训练与推理
  - 分流策略计算
  
- `spring_client.py`: Spring Boot 客户端
  - 封装所有后端 API 调用
  - 统一错误处理

### 2. 数据层 (`data/`)
**职责**: 静态数据文件存储

- `mock_spots.json`: 模拟景点数据（开发测试用）

### 3. 测试层 (`tests/`)
**职责**: 集成测试与单元测试

- `smoke_test.py`: Spring Boot 接口集成测试
  - 验证数据库通路
  - 测试核心 API 功能

### 4. 应用入口
- `main.py`: FastAPI 应用主入口
  - 路由定义
  - 中间件配置
  - 接口实现

## 数据流

### 预测流程
```
用户请求 → FastAPI (main.py)
    ↓
获取景点列表 (spring_client)
    ↓
获取历史数据 (spring_client)
    ↓
LSTM 训练预测 (predictor.py)
    ↓
分流策略计算 (predictor.py)
    ↓
写回预测结果 (spring_client)
    ↓
返回响应
```

### 拥挤指数计算流程
```
用户请求 → FastAPI (main.py)
    ↓
获取最新客流 (flow_simulation_service)
    ↓
构建功能区模板 (crowd_index_service)
    ↓
计算拥挤指数 (algorithms/crowd_index_calc)
    ↓
返回响应
```

### 景点同步流程
```
用户请求 → FastAPI (main.py)
    ↓
解析地区代码 (district_lookup_service)
    ↓
爬取景点列表 (spider/xc_spot_search)
    ↓
写入数据库 (spot_sync_service → spring_client)
    ↓
异步同步详情 (spot_detail_sync_service → spider/xc_spot_detail)
```

## 扩展指南

### 添加新算法
1. 在 `app/algorithms/` 创建新模块
2. 在 `app/algorithms/__init__.py` 导出公共接口
3. 在 `app/services/` 创建对应服务层封装

### 添加新数据源
1. 在 `app/spider/` 创建新爬虫模块
2. 在 `app/services/` 创建同步服务
3. 在 `main.py` 添加对应接口

### 添加新预测模型
1. 在 `app/predictor.py` 或新建模块实现模型
2. 在 `main.py` 添加预测接口
3. 通过 `spring_client` 写回结果

## 配置管理

所有配置通过环境变量管理，在 `app/config.py` 统一读取：

- **Spring Boot 集成**: `SPRING_BASE_URL`
- **数据库配置**: `MYSQL_*`
- **算法参数**: `SCENIC_SEED`, `HISTORY_HOURS`
- **爬虫控制**: `SPOT_DETAIL_SYNC_*`

## 最佳实践

1. **模块独立性**: 算法模块不依赖业务逻辑
2. **类型安全**: 使用 Pydantic 模型和类型注解
3. **错误处理**: 服务层捕获异常，转换为 HTTP 错误
4. **异步优先**: 使用 async/await 提升并发性能
5. **配置外部化**: 所有配置通过环境变量管理
